# App: one control size ladder

Status: accepted
Date: 2026-11-11
Scope: `src/components/ui/` (Button, ButtonLink, IconButton, Badge, Input, InputGroup, SelectTrigger, SearchField, Segmented, the menu items, StatusDot, IconLabel, Icon) and every App screen. Indexed as rules 16, 24 and 35 of `docs/decisions/2026-11-11-work-design-foundations.md`.
Decision: App takes cf0's control ladder (`cf0.ai/docs/decisions/2026-10-28-design-control-size-scale.md`, values from `cf0.ai/docs/decisions/2026-10-31-app-type-match-onboarding.md`).
- One step sets all. A control has one size, a step of the ladder: `xs`, `sm`, `md`, `lg`, `xl`, `2xl`. The step sets seven values together: height, padding, gap, glyph, text size, radius and inset. A control never sets one of them by itself. The step names are `Rung` in `src/components/ui/control.ts`.
- Values per scale. `src/tokens/design-tokens.css` gives each scale (the default, console and onboarding) and the `(pointer: coarse)` blocks their own `--thc-control-*` values. On the App console surface the heights are xs 24, sm 32, md 40, lg 44, xl 44 and 2xl 48px, and the touch height is 44px. On a touch screen a control is never smaller than on a desktop screen.
- Reading the step. A control sets `data-thc-step` on its root. The step blocks in `design-tokens.css` then set the current values for it and its children. Code reads them only through `layout.stepHeight`, `space.stepPadding`, `space.stepGap`, `layout.stepGlyph`, `text.sizeStep`, `radius.step` and `space.stepInset`. `layout.controlHeightXs` to `layout.controlHeightXl` are for a box that must match a control but is not one, for example a skeleton.
- Uses. `xs` badges; `sm` property rows, chips and dense rows; `md` toolbar rows, row actions and dialog actions (the default at `:root`); `lg` inputs, the primary of a page header and menu rows; `xl` large fields; `2xl` the largest controls. `Button` maps its sizes to steps: `xs` to `sm`; `sm`, `touch`, `icon` and `iconHit` to `md`; `md` and `iconTouch` to `lg`; `lg` to `xl`. A toolbar row uses `size="sm"` for every control in it. A page-header primary uses `size="md"`.
- Radius. Every App control uses the step radius (`radius.step`, `web-action-radius-is-step`). A `Segmented` item uses `radius.nestStep2xs` inside its track. App never uses `shape="pill"` (`web-app-no-pill-shape`).
- The inset rule. An icon and its text share one inset, `(height - glyph) / 2` less the 1px border. Every ladder control has a 1px border, transparent when the variant shows none. An `Icon` inside a control has no `size` and takes the step glyph (`icon-glyph-from-step`). A leading or trailing `Icon` replaces that side's padding with the inset. A control with only an `Icon` is a square of the step height. A status dot sits in a glyph-size box. An icon next to static text is an `IconLabel` (`icon-text-row-on-ladder`).
- Hit area. Every interactive control has a hit area of at least `--thc-hit-area` (44px) square through `primitiveStyles.hitArea` in `src/components/ui/primitive-styles.stylex.ts`. Two hit areas never overlap. Under a coarse pointer, App fields use 16px text so iPhone Safari does not zoom.
- One component per role. Add a variant or a step to a component. Do not add a second component or a second size prop (`web-ui-one-component-per-role`).
Rationale: cf0 is the spec for App. cf0's ladder makes the step drive height, padding, gap, glyph, text, radius and inset together, so no call site can drift one of them. The same ladder runs in senvielab and elearning, so a fix in one kit ports to the others.
Evidence: the cf0.ai records above (cf0.ai main @ a0538ec33); senvielab `webapp-control-ladder.md`; `src/tokens/design-tokens.css`; `src/components/ui/button.tsx` (`stepForSize`).
Exceptions: the public site. Its buttons keep the landing's pill shape and `--thc-website-*` tokens.
Bad example: `<HugeiconsIcon size={18} />` in a `Button`; `height: '32px'` on a toolbar control; `<Icon size="sm" />` inside a `Button`; a `StatusBadge` next to `Badge`.
Good example: `<Button size="sm" variant="secondary"><Icon icon={icons.add} />Add</Button>`; `<IconButton aria-label="Close" …>`; `<Badge variant="positive">Confirmed</Badge>`.
Open decisions: none.
