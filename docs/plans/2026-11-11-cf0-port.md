# cf0 port: app.hackcollective.uk

Read this file before you start and before you message another lane. When you finish a step, add one line under Progress.

## Goal

Port cf0.ai's design foundation and its full `./c` toolchain into this repo, the same way senvielab did for work.senvielab.com. This is GREENFIELD: cf0's rules win, and every check lands at zero violations. Anything that needs a baseline or an exemption is a loosening. Stop and report it to the orchestrator. Do not add it yourself.

Two surfaces, one token system, the senvielab shape:

- Public site, hackcollective.uk: `src/` (`src/features/website`). It moves onto a website tier: `src/tokens/website-tokens.css` (`--thc-website-*`), `src/tokens/website-token-consts.stylex.ts`. Today's `--thc-*` landing values move there unchanged. The landing page must render pixel identical.
- App app, app.hackcollective.uk: `internal/` (client, its own Vite entry) and `workers/internal/` (Worker). It uses cf0's three tiers, `src/tokens/{design,semantic,component}-tokens.css`, `src/tokens/token-consts.stylex.ts` and `src/tokens/webapp-globals.css`, all in the `--thc-*` namespace.
- The shared kit lives in `src/components/ui/` and `src/lib/`. It reads the webapp tokens. Public-only components are listed by name in each rule's `exempt`, the senvielab way (see senvielab `base.rules.yaml`).

## Contracts

- Token consts keep cf0's export names (`color`, `space`, `radius`, `text`, `motion`, `size`, `layout`, `cursor`, `mediaQuery`, and the rest), so kit code ports without renames. Website consts are a separate module with their own names.
- Rule ids keep cf0's numbers and names (`web-*`). A rule that applies to the work app scopes to `internal/**`, `workers/internal/**`, `src/components/ui/**`, `src/lib/**` and the webapp token files.
